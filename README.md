# Sorting robot (MTE 121)

A VEX IQ 2nd gen gantry robot with a claw that picks up and sorts boxes by height. Written in C++ and built with the VEXcode extension for VS Code.

## Layout
- `src/`: robot code, one feature per file. `main.cpp` holds `int main()`, where the program starts.
- `include/vex.h`: shared header with shared declarations and constants.
- `makefile`, `vex/*.mk`: build files generated by VEXcode. Leave them alone.
- `.vscode/`: editor and VEX extension settings.

## Building and running
1. Open this folder in VS Code with the **VEX Robotics** extension installed.
2. Connect the Brain over USB (or the controller over radio).
3. Use **Build**, then **Download** (or **Run**) from the VEX extension.
4. Raise the claw by hand to the start mark, place the boxes, and press the Touch LED.

## Rules
- Device objects (e.g. `vex::brain Brain;`, motors, sensors) are the only globals, following the standard VEXcode setup. Define each once only, in `main.cpp`. Other files see them through `extern` declarations in a header.
- Everything else (positions, box data, counters) must be a local variable passed into functions as parameters (by reference when a function needs to change it). `#define` constants are fine.
- Don't duplicate functions across files.

## Coding Rules
- Stay within the scope of the course. Prefer the functions in the Typical VEX IQ Functions section below so the code looks typical; other VEX functions are allowed if they don't break these rules.
- NOT allowed: global variables, infinite loops (e.g. `while(true)`), `break`, a drivetrain, `spinFor`, `spinToPosition`, functions that use callbacks.
- Always use explicit units (`degrees`, `turns`, `percent`, `seconds`, `msec`, `mm`, `amp`) matching the signatures below.
- Use the function and variable names already in the code. Only invent a new name for something the code doesn't have yet.
- Moving a motor (course-required pattern): start the motor with `spin`, run an empty `while` loop until the stop condition is met (encoder position reached, bumper pressed, sensor reading, timer, etc.), then call `stop(brake)` right after the loop. Do NOT use `spinFor`, `spinToPosition`, or other blocking move functions. Example:
  ```cpp
  xMotor.resetPosition();
  xMotor.spin(forward, SPEED, percent);
  while (xMotor.position(turns) < targetTurns) {}
  xMotor.stop(brake);
  ```

## Hardware & Naming
- Devices: X-axis motor, Y-axis motor, claw motor, bumper switch, Touch LED, optical sensor, distance sensor, Brain.
- Device names are arbitrary. What matters is consistency: each device has exactly one name, used the same way in every file. Use the names already in the code.

## Project Requirements & System Architecture

### 1. Hardware & Coordinate System
* **Mechanical Setup:** 2D Cartesian gantry robot with 3 identical VEX IQ motors:
  * **X-axis motor:** Drives horizontal carriage movement along the rail via a **rack and pinion**.
  * **Y-axis motor:** Drives vertical claw movement via a **lead screw**.
  * **Claw motor:** Drives a linkage/gear attachment that opens the claw when spun in one direction and closes it when spun in the opposite direction.
* **Coordinate System `(x, y)`:**
  * **Origin `(0, 0)`:** Top-left home position — claw raised to its highest vertical limit (`y = 0`) and carriage positioned at the left end of the rail (`x = 0`).
  * **Positive `+x` ("forwards"):** Moving horizontally from the origin (`x = 0`) toward the opposite end of the rail (`x = XMAX`).
  * **Positive `+y` ("down"):** Lowering the claw downward from the top rail (`y = 0`) toward the table surface (`y = YMAX`).
* **Sensors & Indicators:**
  * **Side Touch Sensor / Touch LED:** Triggers program start when pressed; lights up **red** if no boxes are detected after the retry scan.
  * **Color / Optical Sensor:** Mounted at the origin end (`x = 0`). Used during homing/reset to verify the carriage has reached `x = 0` (when covered/occluded, the optical sensor's `brightness()` drops to or near `0`).
  * **Bumper Switch:** Mounted at the far right end of the rail (`x = XMAX`). Signals the end of the horizontal gantry travel.
  * **Distance Sensor:** Mounted on the vertical claw carriage (moves with both `x` and `y`). Measures downward distance to detect boxes and compute box height.
* **Calibration Constants:** All physical conversion factors are `#define` placeholders, as in the existing code (`CONVERSION_X`, `CONVERSION_Y`, `SPEED`, `CLAWCLOSE`, `BOXWIDTH`, `XMAX`, `YMAX`, `ARRLENGTH`, `CLAWTIMEOUT`, `SCANSPEED`, `SCANHEIGHT`, `BOXTHRESHOLD`, `BOXTIMEOUT`, `BUFFER`), kept in `include/vex.h` so every file sees them. Add new ones the same way for easy tuning during hardware testing.
* **Units:** all distances are in **mm**. `CONVERSION_X` / `CONVERSION_Y` are motor turns per mm. All boxes are the same width (`BOXWIDTH`); `CLAWCLOSE` is the claw-closing percentage.

---

### 2. Data Structures
* **Box Tracking Array:** Declared in `main()` as `double boxes[ARRLENGTH][2]` and initialized to `0.0` with `fillarray()`. Passed by reference/pointer into functions along with an integer count `m` (number of detected boxes).
  * `boxes[i][0]` = recorded `x`-coordinate of box `i` (from X-axis motor encoder).
  * `boxes[i][1]` = measured height of box `i` (computed from fixed scan height minus distance sensor reading).
* **Current position:** Tracked as `x_cur`, `y_cur` — local variables in `main()`, passed to functions that need them (not globals).

---

### 3. Required Function Signatures & Responsibilities
Names and signatures follow the existing code.

1. **`bool calibrateGantry()`**
   * Moves the carriage horizontally (`+x`) until it triggers the end-of-rail bumper switch, then travels back (`-x`) to the origin `(0, 0)` using known rail encoder turns.
   * Verifies arrival at `x = 0` when the optical sensor's `brightness()` drops to `HOMEBRIGHTNESS` or below (sensor covered). The optical sensor's light must be **off**, or it reads its own reflection as bright.
   * The claw is raised to `y = 0` **by hand** before starting (no top sensor on the y axis); the y encoder is zeroed there.
   * Resets the motor encoders, then calls `clawres()` to open the claw and zero it. Returns `true` if homing succeeds, `false` otherwise.

2. **`void moveto(double x_tar, double y_tar, double &x_cur, double &y_cur, double speed)`**
   * Validates that `(x_tar, y_tar)` lies within the gantry's reachable bounds (`0 <= x <= XMAX`, `0 <= y <= YMAX`). Doesn't move if out of bounds.
   * Converts the target coordinates into motor turns using `CONVERSION_X` (rack and pinion) and `CONVERSION_Y` (lead screw).
   * Moves the X and Y motors to the target coordinates, then updates the current position (`x_cur`, `y_cur`).

3. **`bool boxdetect(double &minDistance)`** (Box.cpp)
   * Triggered during a horizontal scan when the distance sensor registers a significant drop in distance (leading edge of a box).
   * Continues moving at constant scan velocity while timing how long the distance stays reduced, recording the smallest reading (top of the box) in `minDistance`.
   * Waits for a significant increase in distance (trailing edge of the box). If elapsed time exceeds `BOXTIMEOUT` (indicating a false trigger or continuous obstruction), returns `false`; otherwise returns `true`.

4. **`int dataCollection(double boxes[ARRLENGTH][2], bool forwardScan, double &x_cur, double &y_cur)`** (DataCollection.cpp)
   * Resets `boxes` with `fillarray()` and scans along the rail at `SCANSPEED` with the claw at `y = 0`. `forwardScan = true` scans home → bumper, `false` scans bumper → home.
   * When the reading drops below `SCANHEIGHT - BOXTHRESHOLD`, records the starting `x` encoder position and calls `boxdetect()`.
   * If `boxdetect()` returns `true`, stores the box's **centre** `x`-coordinate in `boxes[count][0]` and its height (`SCANHEIGHT - minDistance`) in `boxes[count][1]`, incrementing `count`.
   * Continues until `scanend(forwardScan)` (bumper hit, or `x = 0` on a reverse scan) and returns the total number of boxes detected (`m`). Updates `x_cur`.
   * Distance sensor sits slightly behind the claw in depth (not along the rail), so no x offset is needed.

5. **`void pickupandplace(double xbox, double ybox, double &x_cur, double &y_cur, double x_tar, double y_tar)`**
   * Moves to the box at `xbox` and lowers the claw to `YMAX - ybox` (just above the box).
   * Closes the claw with `claw(false, ...)`, lifts the box to `y = 0`, moves to `(x_tar, y_tar)` (`y_tar` is the drop-off height), opens the claw with `claw(true, ...)`, and raises the claw back to `y = 0`.
   * Helpers: `claw(bool open, double speed, double percentage)` opens or closes the claw by a percentage of its maximum angle; `clawres()` resets the claw's position.

6. **`bool sorting(double boxes[ARRLENGTH][2], int m, double &x_cur, double &y_cur)`** (Sorting.cpp)
   * Bubble-sorts the first `m` entries of `boxes` in ascending order of height (`boxes[i][1]`), keeping each box's `x`-coordinate (`boxes[i][0]`) paired with its height.
   * Divides the total gantry length into `m` equal zones numbered `1` to `m` (`zoneWidth = XMAX / m`), assigning the shortest box to Zone `1` through the tallest box to Zone `m`.
   * For each box (from shortest to tallest): calls `findspot()` with the claw empty, starting from the later of its zone start and the edge of the previously placed box (so order is never broken). Then calls `pickupandplace()` to move the box there, dropping it at `YMAX - height`.
   * Returns `false` if `m == 0` or a box can't find a spot; `true` otherwise.
   * Helper: **`double findspot(double startX, double &x_cur, double &y_cur)`** creeps forward from `startX` until it finds an empty stretch of `BOXWIDTH + 2 * BUFFER` (1 cm each side), returning the centre `x` of that spot, or `-1` if the rail ends first.

### 4. Program Execution Flow (`main`)
1. **Start-Up:** Wait until the side Touch Sensor is pressed, then call `calibrateGantry()`. **If calibration fails**, stop all motors and call `Brain.programStop()` without moving (position is unknown).
2. **Initial Scan:** Run `m = dataCollection(boxes, true, x_cur, y_cur)` from `(0, 0)` to the bumper (`x = XMAX`).
3. **No-Box Handling (`m == 0`):**
   * Call `nobox()`: wait `30` seconds at the bumper end (`nobox()` only waits).
   * `main()` then runs the reverse scan, `m = dataCollection(boxes, false, x_cur, y_cur)`, from the bumper back toward `(0, 0)` to check if boxes were placed.
   * If `m` is still `0`, return to `(0, 0)`, turn the Touch LED **red**, and proceed to shutdown.
4. **Sorting:** If `m > 0`, return to `(0, 0)` and execute `sorting(boxes, m, x_cur, y_cur)`.
5. **Verification:** Skipped if `sorting()` returned `false`. Otherwise **`bool verifysort(int m, double &x_cur, double &y_cur)`** (Verify.cpp) returns to `(0, 0)`, runs `dataCollection()` into its own local `verifyBoxes`, and confirms `verifyCount == m` and that heights are non-decreasing within `HEIGHTTOLERANCE` (`verifyBoxes[i][1] <= verifyBoxes[i+1][1] + HEIGHTTOLERANCE`). `main()` displays `"Sorting Successful"` (Touch LED **green**) or `"Sorting Failed"` (Touch LED **orange**) on `Brain.Screen` line 2.
6. **Shutdown:** **`void shutdown(double &x_cur, double &y_cur)`** (Shutdown.cpp) raises the claw to `y = 0` **first**, then moves to `(0, 0)` (`moveto()` moves x before y, so going straight home could drag the claw through boxes), stops all motors, and calls `Brain.programStop()`.
* Line 1 of `Brain.Screen` shows the current stage (`"Scanning..."`, `"Sorting..."`, `"Verifying..."`, etc.).
